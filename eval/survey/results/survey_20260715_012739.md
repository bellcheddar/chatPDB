**format_pdb_vs_mmcif** (file_format_literacy, 1.2 tok/s, finish=stop)

> What is the difference between the legacy PDB format and mmCIF, and why did the wwPDB adopt mmCIF as the primary archival format?
````
The legacy Protein Data Bank (PDB) format and the macromolecular Crystallographic Information File (mmCIF) format differ fundamentally in structure, flexibility, and capacity for representing structural data.

### Legacy PDB Format:
- **Fixed-column format**: Each piece of information occupies predefined columns, limiting flexibility.
- **Line-based records**: Data are stored in fixed-length lines with specific keywords like `ATOM`, `HETATM`, `HELIX`, etc.
- **Limited metadata**: Metadata such as experimental details, validation metrics, ligand annotations, and biological assemblies are sparse or absent.
- **Hardcoded assumptions**: The format assumes certain conventions (e.g., residue numbering schemes), making it less adaptable to diverse experimental methods like cryo-EM or NMR ensembles.
- **Scalability issues**: The format struggles with large datasets, such as those arising from cryo-EM structures with thousands of atoms.

### mmCIF Format:
- **Structured data model**: mmCIF uses a tabular format inspired by the Crystallographic Information File (CIF), allowing hierarchical relationships between data items.
- **Extensible schema**: New data categories can be added without breaking compatibility, accommodating advances like cryo-EM density maps, NMR ensembles, and integrative modeling.
- **Rich metadata**: mmCIF supports comprehensive metadata including experimental details, validation reports, ligand stereochemistry, and biological assembly definitions.
- **Self-descriptive**: Each data item includes metadata describing its meaning and units.
- **Machine-readable**: Easier parsing and integration into computational workflows compared to fixed-column formats.

### Why wwPDB Adopted mmCIF:
The wwPDB adopted mmCIF as the primary archival format beginning in January 2023 due to several critical factors:
1. **Experimental diversity**: The legacy PDB format lacked capacity to represent data from newer methods like cryo-EM and integrative modeling adequately.
2. **Metadata richness**: mmCIF supports detailed metadata essential for reproducibility and downstream analysis.
3. **Validation integration**: The wwPDB validation reports are naturally integrated into mmCIF files.
4. **Future-proofing**: mmCIF’s extensibility ensures compatibility with evolving structural biology technologies.
5. **Community alignment**: The structural biology community increasingly relies on mmCIF-compatible tools and databases like PDBe, RCSB, and BMRB.

The legacy PDB format remains available for backward compatibility but is no longer the primary archival format. For example, querying PDBe or RCSB for structures deposited post-2023 typically returns mmCIF files by default.

For more details, consult the wwPDB documentation at https://www.wwpdb.org.
````

````
In a Protein Data Bank (PDB) file:

### **ATOM Records**
These records describe the coordinates of atoms belonging to standard amino acid residues and nucleic acid residues found in proteins and nucleic acids. Each ATOM record typically includes:
- Atom serial number
- Atom name
- Residue name
- Chain identifier
- Residue sequence number
- Coordinates (x, y, z)
- Occupancy
- Temperature factor (B-factor)
- Element symbol
- Charge

Example line:
```
ATOM   1234  CA  ALA A  10      12.345  23.456  34.567  1.00 20.00           C
```

### **HETATM Records**
These records describe atoms belonging to heterogens — atoms not part of standard amino acid residues or nucleic acids — such as ligands, cofactors, ions, water molecules (`HOH`), or other non-polymer molecules bound to the macromolecule. The format is identical to ATOM records, differing only semantically.

Example line:
```
HETATM 2345  O   HOH X  200     15.678  26.789  37.890  1.00 22.00           O
```

---

### **REMARK 350**
REMARK records provide supplementary information about the structure deposition and assembly details. REMARK 350 specifically describes the biological assembly information derived from the asymmetric unit coordinates.

It typically includes:
- The number of biological assemblies identified (`BIOMOLECULE: n`)
- For each assembly:
  - Symmetry transformations required to generate the biological assembly from asymmetric unit chains
  - Chain identifiers involved
  - Symmetry operators used (`OPERATION: ...`)
- Notes about assembly generation algorithms used (`Generated by PISA`)

Example snippet:
```
REMARK 350 BIOMOLECULE: 1
REMARK 350 AUTHOR DETERMINED BIOLOGICAL UNIT: DIMERIC
REMARK 350 APPLY THE FOLLOWING TO CHAINS: A,B
REMARK 350 BIOMOLECULE: 2
REMARK 350 AUTHOR DETERMINED BIOLOGICAL UNIT: MONOMERIC
REMARK 350 APPLY THE FOLLOWING TO CHAINS: C
```

This helps researchers distinguish between asymmetric unit coordinates and biologically relevant assemblies derived from symmetry operations.
````

**method_assembly** (experimental_method, 1.3 tok/s, finish=stop)

> Explain the difference between the biological assembly and the asymmetric unit in a PDB entry, and why they can differ.
````
The asymmetric unit and biological assembly are two distinct concepts encountered when working with structures deposited in the Protein Data Bank (PDB):

### **Asymmetric Unit**
The asymmetric unit refers to the smallest repeating unit of the crystal structure that contains all the unique atoms required to build the entire crystal lattice via symmetry operations defined by the crystallographic space group.

- It is the actual structure solved experimentally and deposited into the PDB file (`*.pdb`, `*.cif`, etc.).
- It may contain fewer molecules than are present in the biologically functional complex.
- The asymmetric unit reflects the symmetry constraints imposed during crystallization—not biological function.

Example:
If a protein forms a tetramer in solution but crystallizes with symmetry constraints that allow only two molecules per asymmetric unit, the asymmetric unit will contain two molecules rather than four.

### **Biological Assembly**
The biological assembly refers to the arrangement of molecules that corresponds to the functional form of the protein in vivo—typically the oligomeric state observed physiologically.

- Biological assemblies are often generated computationally from the asymmetric unit using symmetry operations derived from the crystallographic data (`pdbsum`, `PISA`, `PyMOL`, `BioPython`, etc.).
- The biological assembly reflects biological relevance rather than crystal symmetry constraints.

Example:
If the asymmetric unit contains two monomers and the biological assembly requires four monomers arranged tetramerically, computational symmetry operations are applied to generate the tetramer from the asymmetric unit data.

### Why They Can Differ
The asymmetric unit and biological assembly differ primarily due to crystal symmetry constraints during crystallization experiments:

- **Crystal symmetry**: The crystal lattice imposes symmetry constraints that may reduce the number of molecules visible in the asymmetric unit compared to the biological assembly.
- **Experimental limitations**: The crystal structure may capture only part of the functional complex due to packing artifacts or disorder.
- **Biological relevance**: The biological assembly reflects functional interactions observed physiologically rather than crystallographic symmetry.

### Example Calculation
To illustrate the difference between asymmetric unit content and biological assembly content using Biopython:

```python

# Parse asymmetric unit structure

# Count chains in asymmetric unit

```
````

````
To find the corresponding UniProt accession and Pfam domain annotations for a specific chain in a PDB entry, you would use the **SIFTS** database via the Protein Data Bank (PDB) or PDBe (Protein Data Bank in Europe).

### Step-by-step approach:

#### 1. **Obtain UniProt Accession**
Use the **SIFTS mapping data** provided by PDBe or RCSB PDB to map residues in the chain to their corresponding UniProt entries.

Example using PDBe REST API (`https://www.ebi.ac.uk/pdbe/api`):

```bash
curl "https://www.ebi.ac.uk/pdbe/api/mappings/uniprot/PDB_ID/CHAIN_ID"
```

Replace `PDB_ID` with the actual PDB identifier and `CHAIN_ID` with the chain identifier.

#### 2. **Obtain Pfam Domain Annotations**
Use the **SIFTS Pfam mapping** data via PDBe REST API:

```bash
curl "https://www.ebi.ac.uk/pdbe/api/mappings/pfam/PDB_ID/CHAIN_ID"
```

This returns Pfam domain annotations mapped onto residues of the specified chain.

---

### Example using Python (`requests` library):

```python
import requests

pdb_id = "1TIM"
chain_id = "A"

# Get UniProt mapping
uniprot_url = f"https://www.ebi.ac.uk/pdbe/api/mappings/uniprot/{pdb_id}/{chain_id}"

# Get Pfam mapping
pfam_url = f"https://www.ebi.ac.uk/pdbe/api/mappings/pfam/{pdb_id}/{chain_id}"
pfam_response = requests.get(pfam_url).json()

print("UniProt Accessions:", uniprot_response)
print("Pfam Domains:", pfam_response)

### Notes:
````
